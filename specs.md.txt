You are an expert front-end developer and accessibility engineer. Build a complete, production-ready static portfolio website (plain HTML/CSS/JS, no frameworks) tailored for an internship submission to be judged by ~5 software-engineer judges (age 20–40). Follow the requirements exactly and explain decisions briefly for judges.

Core requirements

Goal: A professional portfolio website for an internship judged by software-engineering judges.
Audience & tone: Clear, concise, friendly, professional. Prioritize clarity and technical signals that judges expect.
Visuals & palette: Clean, modern, professional. Use these colors: Primary #3A405A, Accent #B7B5E4, Neutral #C8C6AF. Design dark mode by default, but detect system preference when available.
Accessibility: Meet WCAG AA. Provide a checklist/report showing color-contrast ratios, keyboard navigation, semantic markup, aria attributes, and alternative text for images.
Pages & content

Home: Short hero with name/title, 1–2 sentence summary, CTA to Projects and Contact, visible theme toggle (icon switches between moon/sun).
Projects: Grid/list of projects. Each project entry must include:
Image (placeholder if unavailable)
One-line description
No libraries listed (explicitly omit library lists)
Live project link
GitHub link
Note: include "Auntie Lala's Cleaning" as one project; add a visible note that 3–6 projects are required and user will update remaining projects later.
About: Short bio, one-line role description, skills summary, optional education, no downloadable resume.
Contact: Simple accessible contact form (name, email, message) with progressive enhancement: form posts to mailto: fallback and clear instructions for judges how to test; include privacy note.
Features & behavior

Tech: Plain HTML/CSS/JS (ES6). No build steps required; static site deployable to GitHub Pages/Vercel.
Responsive: Mobile-first, adaptively styled for small → large screens.
Dark/light theme:
Default: dark mode.
Detect system preference via prefers-color-scheme and use that if available; otherwise use dark by default.
Allow manual toggle with a button that switches icon: moon for dark, sun for light.
Persist user preference in localStorage so it stays across visits.
Semantic & accessible:
Use landmarks (header, nav, main, footer) and headings in order.
Ensure keyboard operability and visible focus states.
Provide alt on images and aria-label on interactive controls.
Ensure contrast ratios meet WCAG AA (report exact ratios).
Performance & SEO:
Minimize assets, use optimized images (placeholder SVGs acceptable).
Use semantic HTML and meta tags for title/description and Open Graph.
Include a simple sitemap or note about indexing.
